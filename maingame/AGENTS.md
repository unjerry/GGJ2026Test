# AGENTS.md

## 项目总览

- 这是一个2D横板动作游戏。
- 玩家操控一个从坐标原点出发的点，横板游戏，有一个地面也就是x轴。
- Engine: Godot.
- Keep changes small and shippable.

## 战斗系统

### 敌人设计  

纯几何形状敌人（点射线，两点线段，三角形，方形）  
攻击模式：接触伤害  

### 玩家操作

实心形态：

- 左右移动
- 水平冲刺（攻击/闪避）
- 无法跳跃

### 空心形态  

- 左右移动 + 跳跃  
- 任意方向冲刺（瞄准攻击，鼠标方向）  
- 空中机动性  

### 动态效果  

- 冲刺拖尾  
- 受击闪烁  
- 形态切换变形动画  

### 游戏循环

开局：实心形态，从原点出发  
生存：躲避/击败敌人，避免受击  
形态变化：受击→切换为空心形态  

### 音效设计

移动：简约电子音  
冲刺：矢量划破声  
受击：几何碎裂音  
形态切换：波形变换声  
死亡：正弦波反转  

### 核心体验

策略适应：被迫切换形态后调整战术  
极简挑战：黑白世界中的纯粹动作考验  
视觉冲击：死亡时的全屏颜色反转  
几何美学：点、线、面的动态舞蹈  

### 玩家目标

在敌人包围中尽可能长时间生存  
适应两种形态的不同操作方式  
探索黑白世界的几何美感  

### 后续扩展

玩家击败第一个敌人时获得武器——直线，  
增加获得直线后的玩法  
设计 boss 的各种招式与玩家的交互。

## 编码与改动规则（Coding rules）

- 尽量最小化 diff：能局部改就不要大范围重构。
- 未经明确要求，不要引入新的依赖、插件或第三方库。
- 优先遵循现有代码风格与目录约定；如果仓库里没有统一风格，就保持本次改动内部一致。
- 修改后确保项目能打开/运行；若涉及场景与资源引用，注意 Godot 的路径与导入设置。

### 沟通输出要求（给 Codex 的要求）

- 任何不确定点：先给出 1-2 个方案对比（优缺点/风险），并说明你选择的默认方案。
- 对关键改动：写清楚“改了什么”“为什么这样改”“如何验证”。

## 安全区/禁止改动（Safety / do-not-touch）

- 未经要求，不要修改 CI、发布配置（例如 `.github/`、导出流水线、release 脚本等）。
- 不要无理由重写大文件（尤其是场景文件、自动生成文件、资源导入文件），避免巨大 diff。
- 不要随意改动项目全局设置（Project Settings / Input Map / 渲染设置等），除非任务明确需要，并在说明中列出改动项。
